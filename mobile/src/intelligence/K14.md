# K14 — Local Voice Input

K14 treats voice as an input transport only:

microphone -> local STT -> editable transcript preview -> K13.1 unified router

No voice component can execute a DB operation directly.

K14.0 deliberately uses the existing Bell drag-up gesture for voice capture
rather than always-on realtime transcription.

The existing Bell HOLD gesture remains HOME and must not be reassigned.

Model download remains explicit. Configure a multilingual Whisper-compatible
model URL in voiceModelManager or a later settings screen. Do not auto-download
a speech model on app startup.

Recommended UX:
- tap Bell: command palette
- hold Bell: existing Home action (UNCHANGED)
- drag Bell upward: begin voice capture / reveal microphone target
- release after upward drag: finish capture and transcribe locally
- show transcript
- user can correct it
- "Use this" sends exact text through routeLJingleIntelligence()
- existing HIGH/MEDIUM/LOW confirmation and executor rules continue unchanged

Native setup:
- npm install / yarn after applying fork
- Expo prebuild/native development build required
- Android RECORD_AUDIO permission is requested at runtime
- iOS requires NSMicrophoneUsageDescription in app config/native Info.plist
