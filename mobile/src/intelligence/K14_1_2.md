# K14.1.2 — Context Spine

LJingle context is no longer synonymous with "active timer".

The Context Spine is read-only and derives situational context from the real local
database:

- recently created entities
- recently modified entities
- recently watched/read/played entities via time_sessions
- recent session_contexts
- collection membership / recent placement
- TOPIC links as user-created aliases
- aliases learned in the current runtime only after explicit result selection

Context participates in two places:

1. semanticSearch()
   Context can lightly boost/reorder/surface search candidates. Pure recency is
   deliberately a weak signal.

2. K10 resolveReferent()
   Context is a real candidate source alongside CURRENT, DISCOURSE, LEXICAL and
   SEMANTIC. High confidence still requires strong evidence.

The local language model never sees SQL and never receives authority to mutate
from context alone.

Examples this layer is designed for:

- "the thing I watched yesterday"
- "that movie I added recently"
- "the one in Winter"
- "that Lynch thing" after the user explicitly selected an entity for a
  Lynch-like phrase, or when the entity is linked to a Lynch topic
- recent-media fallback for "lynch movie" when ordinary search has weak results

No database schema changes.
No native changes.
